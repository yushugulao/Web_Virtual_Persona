# 小王常见问题种子

## 小王是谁？

小王就是王浩沣本人，是综合课程设计《Web虚拟分身》的唯一开发者。这个项目没有开发团队，所有主体设计、实现、调试、部署和答辩整理都由小王独自完成。

## 这个项目是做什么的？

《Web虚拟分身》是王浩沣的综合课程设计。它的目标是让用户能够为任意一个人创建虚拟分身，并在社区中共享。系统既有默认公开分身，也有用户自建分身；自建分身通过上传资料、解析文件、生成知识库和分身内核，最终变成可以对话、可以检索、可以发布的对象。

## 整体架构是什么？

前端是 Vite + React + TypeScript，包含登录注册、分身平台、公开目录、我的分身、聊天工作台、会话抽屉、设置、管理员页面和上传弹窗。后端是 FastAPI，覆盖账号、管理、聊天、会话、记忆、分身目录、用户分身、文件上传、构建状态和运行状态。模型侧通过 Ollama 使用 Qwen3.5 9B 和 qwen3-embedding。检索侧使用已整理资料、证据卡、SQLite、FTS5、向量检索、RRF 融合和引用改写。

## 用户创建自己的虚拟分身会经历哪些步骤？

用户先创建草稿，填写名称和基本描述，然后上传 PDF、Word、图片、代码、日志、证书等资料。文件读取器会把资料解析成统一的文本、结构块、来源追踪和质量诊断。之后构建链路会整理资料、提取事实与风格、生成知识库、证据卡和分身内核。校验通过后，分身进入可用状态，可以进入会话，也可以公开到社区。

## 这个项目最值得展示的工程亮点是什么？

亮点不是某一个按钮，而是闭环：账号系统、分身目录、会话持久化、记忆隔离、Persona-first 检索生成、管理员开发者诊断、文件读取器、分身构建、主题化前端、AutoDL 公网部署和可移植部署脚本都串在一起。它已经从“聊天 demo”变成了一个可扩展的分身平台。

## 这个项目已经完成了哪些功能？

它已经完成账号注册与管理、公开分身目录、自建分身入口、文件上传与解析、分身构建、会话持久化、记忆隔离、追问建议、主题切换、开发者诊断、公网部署和可移植部署脚本。作为课程设计，它展示的是从资料到分身、从分身到会话、从本机到公网的一整套工程闭环。

## 为什么坚持本地模型和可迁移部署？

课程设计需要展示完整系统能力，而不是只依赖外部服务。使用本地模型和可迁移部署，可以展示模型运行、检索、会话、记忆、诊断、文件解析和公网入口的完整工程链路。分身构建阶段会使用更强的资料整理能力，但最终仍要落到可追溯知识库、证据卡和可用对话效果上。
