# Web虚拟分身

## 项目目标

《Web虚拟分身》是王浩沣独自完成的综合课程设计，目标是让用户能够为任意一个人创建虚拟分身，并在社区中共享。它既能展示系统默认的公开档案分身，也能让普通用户上传资料、创建自己的分身、进入会话、发布给其他人使用。

## 产品结构

登录后用户先进入分身平台首页，选择“与公开的虚拟分身交谈”或“我创建的虚拟分身”。公开目录提供搜索、系统默认分身和其他用户公开分身推荐；我的分身页面展示用户自己的分身、创建入口、详情弹窗和公开 / 取消公开操作。聊天页提供会话抽屉、思考强度、消息流式输出、追问建议、设置、运行状态和管理员诊断。

## 后端技术框架

后端使用 FastAPI，核心能力包括账号认证、管理员管理、系统分身、公开分身目录、用户分身、会话、记忆、聊天流、状态监控、文件上传和分身构建。SQLite 负责账号、会话、记忆、上传文件、构建状态、评分事件和运行记录。

## 检索与生成

系统默认分身和用户分身都通过 Persona-first 检索生成回答。检索资料包括已整理的 Markdown 资料、证据卡、问答种子、时间线、个人简介、语气风格和用户分身私有知识库。检索采用 FTS5、向量检索和 RRF 融合，生成侧使用 Ollama 本地 Qwen3.5 9B，并按低 / 中 / 高努力程度控制思考预算和回答风格。

## 会话与记忆

会话是持久化的。用户可以归档、恢复或删除会话；同一会话内有短期上下文继承，使用最近原文和滚动摘要；长期记忆按用户、会话、分身隔离；用户全局记忆可以在同一用户的不同会话和分身之间共享，但归档 / 删除会影响其可用性。

## 用户分身创建

用户创建分身时先填写名称和基本描述，再上传资料。文件读取器会把 PDF、Word、图片、代码、日志、表格和截图等资料解析成统一文本、结构块、来源追踪和质量诊断。分身构建链路会整理资料、修复 OCR 噪声、提取事实和风格、生成知识库、证据卡和分身内核。校验通过后，用户分身进入可用状态，可以进入会话或发布到公开目录。

## 文件读取器

文件读取器的目标是强上限、多后端、可追溯。数字 PDF 和 Office 优先走 Docling；图片、扫描 PDF、截图、复杂表格、公式和图表走 Marker/Surya CUDA。低质量解析不能静默通过，必须记录解析方式、质量分、警告和复查建议。

## 前端与主题

前端使用 Vite、React 和 TypeScript。主题包括“黑与灰”和“蹦蹦炸弹！”。黑与灰偏冷静编辑式界面；蹦蹦炸弹偏可莉冒险手账风格。前端关注的不只是美术，也包括按钮是否清晰、运行状态是否遮挡内容、会话列表是否可读、上传进度是否透明和移动端是否溢出。

## 部署

公网演示使用 AutoDL 运行后端和 Ollama 模型，阿里云 ECS 只作为 Nginx + frps 公网入口。项目已经整理出可开源部署能力：公开导出、安全扫描、Windows / Linux 部署向导、依赖自动检测、官方来源下载、模型透明拉取、frp 内网穿透和直接公网部署选项。

## 完成状态

项目主体已经完工。对外介绍时，应强调它已经完成从资料上传、分身构建、会话使用、公开分享到公网部署的闭环；不要把它说成仍处在开发中的待完成系统。
